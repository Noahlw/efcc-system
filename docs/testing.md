# Testing workflow

Authority: [Spec #66](https://github.com/Noahlw/efcc-system/issues/66), tickets #67–85 and current source. Historical source-scoped evidence lives in the corresponding tickets and [#85](https://github.com/Noahlw/efcc-system/issues/85); it is not qualification of later edits. Accepted product visuals and the Design Book are unchanged.

For the shared PR body, flexible UI Preview, evidence and reviewer responsibilities, see the [Pull Request Delivery Contract](agents/pull-request-contract.md).

## Toolchain and commands

Use Node **24.21.0**, pnpm **10.33.2**, the checked-in lockfile and installed Playwright browsers. Bootstrap with `pnpm install --frozen-lockfile --prefer-offline`; missing locked packages may be downloaded. Install scripts are not globally disabled. The GitHub `pull_request` workflow tests its merge commit, validates the event base/head/tested source identities, runs actionlint, check and typecheck, then measures the existing unit suite. The source map determines whether a change also requires production build and Native HTTP/browser qualification; documentation-only paths skip browser installation. The stable `checks` job is only a branch-protection block after a GitHub ruleset marks it required; that setting is verified separately.

| Command | Actual boundary |
| --- | --- |
| `pnpm test` | Fast Vitest Node contracts, SSR/static component tests and tooling tests; no interactive-browser claim |
| `pnpm test:coverage` | The same production-source unit selection under pinned V8 coverage; no Native or interactive-browser claim |
| `pnpm test:mutation` | Informational Stryker pilot for account identity-validation against its direct existing application contract tests; not the Native suite |
| `pnpm test:e2e` | Complete live native foundation, HTTP/browser, causal and required dev lanes |
| `pnpm test:affected [--base origin/main]` | Branch vs PR base plus current uncommitted source, fail-closed source-impact selection |
| `pnpm test:staged [--full]` | Exact Git index including partial staging; explicit full permits otherwise unclassified paths |
| `pnpm test:qualify` | Complete immutable candidate check, typecheck, fast tests, production build and agreed native matrix |
| `pnpm test:native` | Cached native build plus built ingress/D1/auth/isolation/lifecycle compatibility cases |
| `pnpm test:features` | Cached native build plus feature HTTP/browser projects |
| `pnpm test:causal` | Cached native build plus execution-time deadlines, held writers and durable recovery |
| `pnpm test:dev` | Required native Vite hydration/status case; not the default runtime |
| `pnpm build:cached` | Immutable native artifact graph only; never cached test results |

CI uses `pnpm test:coverage` as its unit run rather than running both `test` and `test:coverage`. The candidate report measures every executable `src` `.ts` and `.tsx` file under the checked-in policy, including unimported files, and excludes declaration-only `.d.ts` files. For a comparison, the runner checks out the actual PR base in a separate worktree and runs that source with its own lockfile and production dependencies, overlaying only the candidate's pinned coverage config/provider. The base's ordinary `vitest.config.ts` must be byte-identical to the candidate's; otherwise the result is `INCOMPARABLE`. The tested commit, event head, base commit and source tree are recorded with the report. If the base cannot be reproduced with the same policy and compatible measurement tooling, no delta is shown. Coverage has no percentage threshold, the action writes an Actions step summary only, and no raw coverage report is uploaded as an artifact or written to a PR comment. With comments disabled, the action's per-file rows are useful for locating modules but do not classify changed-source groups or assign test ownership.

Direct native commands require an owned clean checkout without local vars; the Git gate is the normal route from a developer checkout. It exports only the authoritative Git tree to a private disposable source, validates privacy, installs that snapshot's locked dependencies/config and executes its own policy. Do not move/delete personal `.dev.vars` or `.wrangler` to run tests. Tests do not invoke `db:reset:local`. That explicit destructive developer command and `db:migrate:local` operate on developer D1 and require separate authorization; they are not test setup.

## Mutation pilot

`pnpm test:mutation` uses Stryker against only `src/features/account/identity-validation.ts` and the existing `tests/shared/account/application-contract.test.ts`. Its isolated Vitest config retains the repository aliases while restricting test discovery to that contract file. CI runs this pilot only when the existing source-selection policy marks a full qualification/toolchain change, the Identity-validation implementation, its direct contract test or mutation config; documentation-only changes do not trigger it. The run executes the selected Node tests for generated mutants; it does not run Native HTTP, D1 or browser cases per mutant. The runner validates the report schema and exact file scope, then publishes only category counts, score, runtime and source identity to the Actions summary. Raw Stryker JSON contains source and replacement text, so it remains ignored and is never printed or uploaded. Keep the score informational: do not set a pass threshold, exclude surviving mutants to raise it, or treat surviving and uncovered mutants as confirmed product defects. Review category counts to decide whether existing behavior is meaningfully asserted; setup failures and timeouts remain distinct from test outcomes.

The initial implementation pilot produced 125 mutants in 13 seconds: 25 killed, 91 survived, 9 with no coverage, 0 timed out and 0 errors. Stryker reported a 20.00% total mutation score and 21.55% for covered mutants. The uncovered mutants were in username validation; survivor examples also showed email and phone alternatives the selected contract suite did not distinguish. This is a narrow test-strength signal, not a whole-repository quality baseline or evidence that the current production behavior is wrong. The machine-readable result is written to ignored `coverage/mutation/mutation.json` and is regenerated by each run.

Stryker 10.0.0 currently requires a TypeScript compiler API that the repository's TypeScript 7.0.2 no longer exposes. A pnpm `packageExtensions` entry gives only `@stryker-mutator/core@10.0.0` its own TypeScript 6.0.3 dependency; the application and root typecheck continue to resolve TypeScript 7.0.2. The runner is named explicitly in Stryker's `plugins` list because strict pnpm dependency links do not make a sibling runner discoverable through Stryker's package-local wildcard search. Revisit both tool-only compatibility settings when a Stryker release supports the root TypeScript API and resolves the runner correctly under pnpm; verify the real mutation run before removing them.

## Gate, selection and evidence

One Husky pre-commit uses native lint-staged formatting and the staged gate. Native lint-staged owns partial-hunk hiding/restoration, backup/revert and staging formatter edits; the coordinator adds no custom stash or auto-staging of generated outputs. Index drift fails closed. Unknown paths/renames/deletions require a mapping or explicit `--full`, not silent auto-full. One explicit source-area/risk map selects claim tags and source-sensitive engine intent; an unfiltered collection-only native `--list` first validates definitions against the complete runtime/engine matrix. The collection project never executes. Runtime configs then resolve executable cases/projects. CLI `--grep` intersects project transport filters, and `--project` selects mobile scope. Config changes select that config directly rather than synchronizing another family-tag union; required discovery must be nonempty and classified, and execution must match discovery with no skip/retry. Shared auth/DB inputs select independent semantic boundaries rather than one happy path per file. HTTP runs once; mobile projects select engine-sensitive cases.

The local gate prints immutable source/base identity, changed paths, selection, toolchain, expected/executed Native cases, failures/skips/retries and private evidence locations. CI logs retain source identities and safe aggregate counts, while command output, raw Native IDs, logs and traces remain private. Failure is not waived by CI, a historical run or a later retry. Preserve the first failure; after repair refresh the changed boundary and required final qualification. Never bypass required checks: do not disable Husky, use `--no-verify`, skip required tests or weaken formatting, typecheck or CI gates. Fix failures before committing or publishing; if a required gate is blocked, preserve the evidence and report the blocker without submitting the change. No pre-push gate or cached-pass service exists.

Avoid redundant validation: during implementation use changed-path checks and distinct native counterexamples. Freeze the contracted candidate before the complete qualification. Do not chain full `qualify`, `affected` and `staged --full` merely because they are different aliases. Staged fidelity, selection, privacy and interruption have their own targeted counterexamples; passing results are never reusable cache artifacts.

Owned process-group cleanup is complete only after native signal zero confirms that the group is absent. A permission error is not evidence of absence. If absence cannot be confirmed within the cleanup bound, the command fails; owned descendants/listeners cannot be silently abandoned. Historical deleted-path mappings classify PR-base changes; their strings are not active legacy implementations. [#84](https://github.com/Noahlw/efcc-system/issues/84#issuecomment-6165625298) retains the detailed retirement/equivalence history.

The runtime boundary check uses the installed TypeScript compiler API to discover current `src` client roots and resolve their local runtime imports, including aliases and re-exports. `pnpm check` and Vite configuration both enforce it. Type-only server contracts remain valid; server composition roots are not client roots, and local cycles are reported rather than rejected. `node scripts/runtime-boundaries.ts` emits the current source/client/server inventory and any forbidden dependency traces, so added, renamed and removed owners are discovered without a handwritten root list. This is a bounded local-source check; actual client builds still qualify package dependencies and framework transforms.

## Runtime and scenarios

Wrangler `createTestHarness` owns Worker lifecycle, internal ingress and original migrations. The srvx Node listener uses public `node.keepAliveTimeout: 0` and forwards through native Harness routing to the built Worker; explicit fixture cleanup owns idle connection closure. A real app wire regression crosses the former five-second timeout plus one-second buffer and verifies explicit closure. The separate inner SDK five-second transport counterexample remains recorded in ADR0002 and the current aggregate receipts. `NativeApp.close()` releases both native owners; do not close only `app.harness`. Redirects remain browser-visible and no request retry is added (ADR0002). Playwright owns worker/test resources and fresh native contexts. Ordinary cases share one store per execution worker (default2) with case-owned users/rows/limiter identities; schema/global/race scenarios explicitly select a fresh dedicated store. No scenario resets tables halfway through. D1 assertions use the application's actual `getEnv().DB` statements/batches, not per-query Wrangler CLI or another proxy.

A test-only default Worker RPC creates genuine Better Auth credentials plus necessary EFCC domain prerequisites. Normal authenticated browser setup uses production HTTP login and native in-memory `storageState`; no synthetic cookies or saved auth files. Production has no seed route/token, Staff bootstrap or test control entry. Native verifier-success and actual D1 batch barriers retain their causal semantics; fault/deadline effects traverse the production guard/dispatch pipeline. Persistent Worker update tests preserve durable effects and rebuild execution state; harness reset is not a cold-crash guarantee.

See ADRs [runtime](adr/0002-native-testing-runtime.md), [presentation](adr/0003-native-presentation.md), [causal controls](adr/0004-native-causal-controls.md) and [immutable builds](adr/0005-native-immutable-builds.md) for retained narrow seams and limitations. Pure synthetic domain fixtures and independent business expectations remain EFCC-owned.

## Builds and privacy

Only the immutable app/provisioning/causal/credential `dist` graph is cached through pinned native Turbo local-only storage in Git's common directory. Inputs include compiled test helpers/controls, app source/assets/migrations, configs, lockfile, actual toolchain and build environment. Assertion-only changes can reuse output only without compiled consumers. Tailwind discovery is `src`-scoped in the stylesheet for both native and production builds; production remains uncached. Missing/corrupt cache rebuilds; unavailable storage executes uncached. A real build failure blocks tests. Native resolved inputs undergo source privacy checks before restore/publication, including ignored files captured by compiled globs.

No DB/cookies/sessions/passwords/member data/raw traces/results/pass are cache inputs/outputs. Generated dist and `.turbo` stay ignored. Emitted relative Wrangler metadata preserves assets/migrations/config graph portability; do not copy developer vars beside it. Private logs/traces/HTML reports are not publishable artifacts. Source privacy is fail-closed classification, not a general secret scanner; only synthetic data is permitted.

## Browser and presentation evidence

Chromium covers all browser journeys; iPhone WebKit and Pixel Chromium cover critical auth/review/restriction/recovery/cookie/history/secret/draft/mobile claims. HTTP-only cases run in one project. Required dev and causal configs remain separate. Viewports, root-font scaling and device profiles are emulation, not physical devices, system zoom, PWA or soft-keyboard proof.

`qualifyPresentation` requires explicit draft and critical-action locators (optional focus/masks). Layout, overflow, root-font, reachability, focus and draft invariants execute before optional capture at all eight contexts plus the project's original viewport. Success PNGs require `EFCC_CAPTURE_SUCCESS=1`; Playwright owns screenshots, original-byte masks, attachments and reporters. Capture off/on is a distinct equivalence check, not a reason to duplicate HTTP/deadline/dev runs. Secrets/password controls are masked in screenshot bytes; traces/logs may still contain private data. No custom gallery/writer/uploader or second workflow driver exists. Design Book reference/offline-gallery verification remains separate from application capture.

The Axe baseline is deliberately limited to three states: the sign-in desktop state, Applicant correction validation-error state across the mobile browser matrix, and Staff creation review state across that matrix. Violations are attached as report-only findings; Axe execution errors fail the case. These scans do not certify unscanned screens, keyboard behavior, physical devices, VoiceOver/TalkBack or human accessibility acceptance. Runner qualification binds each attachment to the immutable source tree. Direct Native commands without runner metadata label the attachment `UNBOUND` and are not source-affine evidence. For workflow permissions, dependency scanning and scheduled dependency-update policy, see the [CI security contract](ci-security.md).

For final capture parity, native `presentation` annotations identify the cases that actually called the helper in the complete successful run. Assemble a temporary native Playwright `--test-list` from that report's exact project/file/suite/title identities, verify identical IDs/projects through `--list`, then run only that list with the opposite `EFCC_CAPTURE_SUCCESS` value and `--retries=0`. Compare native execution scope and masked attachments. This is artifact assembly, not a second business driver or maintained case registry; do not rely only on `@risk-presentation`, which is not present on every historical consumer. Reuse the immutable build, not validation results.

## Authorization and delivery

Destructive fault/interruption and cache corruption probes require scoped authorization and owned disposable synthetic resources. Existing agreed qualification scenarios operate only on harness-owned stores; additional exploratory probes need separate authorization. Never personal/remote D1 or production data. No deployment, merge or force-push is implied. Final delivery records exact candidate identity, observed clean results, independent review, bypasses and unperformed gates; implementation, qualification, owner acceptance and release are separate states.

## Add or change a scenario

Use the existing native `test` fixture; perform the real operation and keep independent assertions visible. Ordinary cases own accounts/sessions/rows/IP identities in their worker store. For schema/global/race claims, override `caseApp` with `dedicatedApp` so account provisioning, auth/request contexts and observations use the same store. Never replace this dependency override with a test-body alias or reset inside a scenario.

`tests/e2e/account-assisted/` groups credential lifecycle, actor/authority, transaction rollback and Staff UI behavior. Its family/transport tags inherit through native `test.describe`; cases declare semantic risks and mobile-critical claims. Ordinary Staff browser setup requests `staffPage` (alias it as `page` in the case). Its genuine Staff HTTP-login state belongs only to that fresh browser context, never a test-wide `storageState` override or the public `request` fixture; browser login/session-transition claims keep their actual steps. Fault→rollback→restore→same-key retry stays one case. Shared domain inputs/observations are in the family fixture; they do not replace independent expected effects.

Add ordinary specs anywhere under `tests/e2e/**/*.spec.ts`; no config registration is needed. Ordinary/dev definitions require `@native`, exactly one transport (`@http` or `@browser`), and known semantic risk tags; `@mobile-critical` requires a browser claim. Foundation and causal configs retain their separate ownership; `@lifecycle` selects the serial foundation cleanup project independently of case wording. Use the native `dedicatedTest` preset for a plain fresh store; domain/causal extensions retain their dependency overrides when they extend a different fixture base. Split mixed HTTP/UI families only where the responsibilities differ; keep causal sequences and their independent effects together. Definitions must have an exact full runtime/project counterpart before affected selection is accepted. Changed production source requires the explicit impact mapping; unknown paths block. Verify selected cases/projects through native discovery, then execute that same selection. Full qualification retains all browser/HTTP/causal/dev claims.

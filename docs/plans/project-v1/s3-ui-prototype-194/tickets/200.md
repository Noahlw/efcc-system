## What to build

From one Program, an authorized manager opens candidate search, selects eligible people across bounded pages/queries, checks selected-only view and grants them in one all-or-none Save. The picker’s plus/minus only changes unsent selection until Save.

## Acceptance criteria

- [ ] Several explicitly selected eligible people become Leaders in one Program via one original operation; each required effect occurs exactly as the business spec requires.
- [ ] One target eligibility/membership change, Program move, authority loss, already conflicting assignment or required-effect failure proves no partial changes on real native storage.
- [ ] Selection survives same-task search/page changes, selected-only/count accurately reflect the full set and Reset cancels only unsent choices.
- [ ] Plus/minus is quiet, labelled, pressed-state accessible and reduced-motion safe; minus never means stored assignment withdrawal.
- [ ] At/over the justified command cap, duplicate targets, command-family key collision and changed intent are covered without implicit chunking.
- [ ] Known no-write stays editable; whole conflict requires fresh explicit selection; UNKNOWN resolves original command and cannot trigger partial retry or replacement Save.

## Implementation method

1. Add a separate explicit same-Program grant-only aggregate command/result/reconcile shape. Input is one Program, explicit deduplicated target IDs and one original actor/key/fingerprint; use the #197 aggregate infrastructure/key registry while preserving this command’s distinct intent. No bulk withdrawal, cross-Program batch or select-all-search mode. Derive a finite target cap from actual per-target effects/parameters/statement budget and reject invalid/over-limit commands before any write.
2. Reuse current native Program eligibility and permission guards for every selected person at SQL execution, including current Program owner and DM Department membership restrictions. All target assignments and mandatory per-person history/Audit/Inbox plus aggregate receipt commit atomically. A single ineligible/stale/already-conflicting target or required-write/guard miss prevents the whole set. Do not call the single-grant endpoint in a loop or commit chunks behind one Save.
3. Adapt bounded candidate projection/search to return only authorized eligible minimal identities. Keep explicit selected IDs plus minimal authorized labels across query/page changes in one Program task, not an account directory cache. Provide selected-only view, selected count, Reset and bottom Save. Query/filter change must not remount the task or discard choices; Program/actor/authority boundary must dispose protected selection.
4. Candidate icon button is quiet, min44px with stable accessible identity/action naming and aria-pressed; animate + to minus only as selection feedback with reduced-motion fallback. Minus cancels an unsent choice, never withdraws a stored Leader. Header add opens the picker and has an explicit accessible name.
5. Reuse shared task/proof/original-operation lifetime. Whole-batch conflict retains old selection solely as a read-only exception reference, refreshes current authorized eligibility and requires reselection; known no-write on unchanged baseline keeps choices and search usable. UNKNOWN reconciles only original operation, never retries a remainder or infers success from Inbox/receipt absence.

## What to build

The same person task now edits nested Department Manager and Program Leader duties together, submitting one mixed reviewed set atomically and returning to fresh responsibilities. Program reassignment, eligibility change or one stale witness rejects the whole reviewed set.

## Acceptance criteria

- [ ] One mixed Save updates permitted DM and PL duties for one person with all-or-none assignment/history/Audit/Inbox/receipt effects.
- [ ] A stale PL witness, moved Program, changed eligibility/authority or failed required later effect leaves both DM and PL writes absent.
- [ ] Nested UI and known baseline statuses remain readable and accurate across bounded pages; unloaded entries and reverted changes are omitted.
- [ ] Operation fingerprint binds role, scope, action, target and witness; no cross-kind key collision or replay changes intent.
- [ ] Fresh overview accurately reflects confirmed mixed results; known no-write/conflict/UNKNOWN follow their distinct established transitions.

## Implementation method

1. Extend #197’s explicit aggregate union with Program Leader scope/action/exact withdrawal witness; do not add a second person-batch controller or a generic permission editor. Include role kind and current Program-to-Department ownership in validated canonical intent and SQL-time guard responsibility. Enforce each role’s actual permitted target/cleanup matrix independently.
2. Extend the native aggregate execution and mandatory per-change history/Audit/Inbox/receipt semantics to mixed sets. A Program moved/deleted/restricted/changed after load, loss of delegation or stale assignment identity must prevent every member effect. Retain current single Program Leader command compatibility and existing original actor/key ownership.
3. Extend independently authorized assignment-status reads for visible nested Programs. Separate bounded catalog/page discovery from known current assignment state; do not calculate unchecked from absence on a page. Keep the known explicit net map stable while browsing within the same person task and preserve unloaded/untouched scopes.
4. Extend the #197 editor hierarchy: Department Manager under Department, nested 聚會負責人 choices under each Department’s Programs; pending grant/withdraw markers and concise Cantonese errors. Reuse the #196 shared actions/proof and #197 conflict/UNKNOWN handling. Task origin can carry a permitted Program restriction for #199; it is presentation context, never server authority.

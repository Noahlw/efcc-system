## What to build

From the person overview an Admin changes Member/Staff identity in a focused task, resets an unsent choice, confirms credentials only when needed and returns to fresh authorized detail after an authoritative outcome. This real mutation establishes the shared S3 header/footer/proof composition for later tasks.

## Acceptance criteria

- [ ] Admin Member/Staff change completes with existing atomic cleanup and required effects; protected targets and non-Admin callers stay denied.
- [ ] One reusable bottom action region works with 320px, desktop, long content/errors, 200% text, reduced viewport height and software keyboard; no field/focus is covered.
- [ ] Valid proof causes no extra prompt; missing/expired proof retains values and requires explicit second Save; expired authentication is not treated as missing proof.
- [ ] Reset restores known unsent baseline; Keep/Discard works; pending and UNKNOWN retain original operation identity and cannot silently submit again.
- [ ] Known no-write retains valid choices; confirmed save returns to freshly authorized overview; actor/authority replacement discards protected state and late responses.
- [ ] All new shared controls use existing typed variants: quiet icon controls, primary task progress, secondary Reset/cancel/navigation; no destructive styling for ordinary identity edits.

## Implementation method

1. First extract the smallest shared S3 task frame around the existing RootFrame/PageFrame and TaskHeader owners: header, one scrollable content region and a viewport-bottom action region outside that scroller. Reserve real space; do not create nested page scrollers or a fixed overlay with guessed content padding. Compose content/actions slots, not role booleans. Keep desktop sidebar; focused phone edit/proof hides browse nav and restores it on return.
2. Adapt the existing Global role Member/Staff command into its own focused form, using useAppForm and strict current contract. Identity, Membership and scoped duties remain distinct. Staff exit cleanup and its required Session/history/Audit/Inbox/receipt effects remain in the existing atomic server owner. Separate Role Assigner and Admin commands are delivered by #201/#202/#203, not silently bundled here.
3. Reuse role-command-lifetime and Security-owned ten-minute credential confirmation. Extract only private Security form presentation needed to compose it; reuse the existing password-confirmation protocol, Base UI focus/labels and supported pinned APIs. Valid proof is reused. Missing/expired proof retains the same authorized unsent task and returns for another explicit Save; authentication expiry follows the existing auth path. Never key/remount the task by proof freshness, query or viewport.
4. Shared bottom actions show net dirty count/Reset/Save for ordinary settings. Reset affects only unsent state. Pending and UNKNOWN do not become new editable drafts; disable duplicate submission and settle only the original operation. No separate visible 變更摘要 block is added. Keep target/action/role/scope and consequences clear in the relevant task/proof/exception presentation.
5. Use the existing unsaved departure owner for Keep editing/Discard before an app-controlled target/scope/route change. Clear protected task and proof state on actor/authority replacement; ignore late responses. Do not persist protected drafts/passwords/identities in storage or URLs. Known no-write on an unchanged baseline keeps editable choices; confirmed outcome refetches under current authority.

Preserve valid same-task choices through conditional proof and known no-write, distinguish auth expiry, dispose protected state on actor/authority replacement and ignore late responses. UNKNOWN is neither success nor definite failure and never authorizes a replacement Save. No protected draft/password/person record storage in URLs or persistent browser storage.

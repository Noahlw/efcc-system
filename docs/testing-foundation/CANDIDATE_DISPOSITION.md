## Spec axis — actionable blockers and counterexamples

### S1 — Delete the second D1 owner rather than adopting its async facade (P1)

**Anchor:** `tests/support/db.ts:14–20`, P:9435–9441; consumers P:7897–7901 and P:8571–8600. #66 decisions 6–9 / CF01, #67 acceptance require the app’s actual binding, original migrations and native runtime lifetime. The candidate creates `getPlatformProxy` with a persisted directory, while the app runs Vite and migrations run CLI. The new foundation test demonstrates an intended app↔persisted-proxy check, not sole app-binding ownership; it neither checks migration tracking nor another unaffected store. This is a source-proven architectural noncompliance, **not a claim that the proxy necessarily observes the wrong database**. Delete `db.ts`, migrate every caller to the actual app binding, and rewrite its test around app binding/provisioning plus migrations/ABORT/IGNORE/isolation. Do not preserve the facade as an alias.

### S2 — Pace the request’s actual limiter identity, not a process-global fixture value (P2)

**Anchor:** `tests/scenarios/limiter.ts:31–35`, P:8618–8622. The helper now considers only `EFCC_TEST_IP`, but existing manual contexts do not necessarily use it: `staff-fixture.ts:49–57` replaces it with a random explicit IP; `account-security.spec.ts:62–69` uses fixed `198.19.0.10`; `account-identity.spec.ts:145–151` uses an explicit random IP and `:193–195` omits it. When one of those actual request buckets remains full, `waitForSignInWindow()` observes a different bucket and returns before that bucket opens, so callers expecting successful authentication can receive 429. The baseline path-suffix scan considered that bucket; this is introduced by the exact-key filter. Smallest durable repair is migration to case-owned native contexts with an explicit identity contract and retirement of ordinary pacing; any temporary pacing must receive the actual request identity. Do not reintroduce the global scan permanently. No runtime failure was reproduced or claimed.

### S3 — Reject private state outside the narrow named-directory blacklist (P1)

**Anchor:** `scripts/test-snapshot.ts:68–75`, P:9090–9097. #66 decision 16, #82 acceptance require protection for auth/session snapshots, SQLite/D1 state, member data and raw artifacts, not just gitignore. A tracked/force-added `auth-state.json`, `fixtures/local.sqlite` or raw trace outside `.wrangler`, `test-results`, or `playwright-report` is not rejected by this predicate and is exported; a nonignored equivalent is also copied in working-tree mode. Its bytes are retained with failure/capture snapshots. Existing tests only exercise `.dev.vars` and `.wrangler` sentinels. Implement the agreed privacy policy at export/bootstrap/evidence boundaries and add synthetic counterexamples for these categories; explicit synthetic inputs must remain usable. This is a static guard bypass, not an assertion that any real private artifact currently exists or has leaked.

### S4 — Restore required classification and command semantics (P1)

**Anchors:** `scripts/test-selection.ts:45–48`, P:8997–9000; `package.json:26–29`, P:51–54; `playwright.config.ts:11–15`, P:82–85. #66 decisions 14–19, #82 require unknown fail-closed or **explicit** full qualification, shared-risk semantic subsets, native classification/nonempty discovery, affected/staged/qualify commands. Candidate silently selects full for unknown/shared input, recognizes only HTTP/resilience tags, and has no required-claim discovery check. `docs/foo.ts` is classified as documentation regardless of extension at P:8969, so that unknown executable path bypasses all checks. Required affected/staged/qualify commands are missing; mobile projects still match only three entire files. Also `test:resilience` excludes the public-application rollback at P:1311–1315 and the assisted native-verifier race at P:1882–1886 because these are tagged only HTTP. Rewrite the small impact/risk map and native projects/tags/discovery, fail on unclassified/empty required claims, expose the required commands, and update policy tests. Do not infer that the entire full suite omits those HTTP cases: `test:e2e` still selects them.

### S5 — Use the approved locked bootstrap instead of forced offline/no-hooks (P1)

**Anchor:** `scripts/test-runner.ts:111–117`, P:8874–8880. #66 decision 17 and #82 explicitly reject candidate `--offline --ignore-scripts`. Replace with frozen-lockfile/prefer-offline bootstrap from snapshot policy/config and honor required install behavior. Preserve failure blocking and disclose downloads. No assertion that all installed binaries fail is warranted without executing this boundary.

**Anchors:** P:1889–1902 / P:5820–5831 auxiliary process changes; P:7884–7947 seed reexports; P:9482–9523 fixture lifetime/IP; P:8870–8923 bootstrap/ports/vars/migrations. #66 CF02–CF09, #67, #69–80, #84 require case-owned accounts/stores, special fresh stores, canonical test-only RPC, production pipeline and public verifier. Migrate their consumers and delete obsolete owners after equivalent proof; preserve real schema/ABORT/IGNORE/batch/verifier/recovery causes. **Anchors:** P:7500–7523 metadata capture; P:8716–8753 workflow documentation. #66 decisions 20–22, #68/#83/#84 require native capture/attachments/reporters, explicit draft/action locators, immutable build reuse/integrity/compiled-test invalidation.

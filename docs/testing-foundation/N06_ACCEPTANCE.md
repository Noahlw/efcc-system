## Fast contract-test cleanup

`tests/shared/application-contract.test.ts` remains unchanged: it already imports only `node:crypto`, Vitest, and the production application schemas. Its existing Node assertions remain part of `pnpm test`; there is no obsolete Playwright, seed, environment, or fixture dependency to remove from this file.

The two owned feature specs no longer import their legacy seed, shared-origin, pacing, wait, or generic request/SQL setup helpers. Scenario actors are created through public HTTP and authenticated through the real username sign-in route. Independent expected state is checked directly through the selected `caseApp.db`. Cases that mutate global state, create cross-account conflicts, exercise concurrent behavior, or install fault triggers select the native `dedicatedApp` through the local `caseApp` extension; other cases use uniquely generated actors on the selected worker application. The cross-account applicant case uses the narrow `crossAccountApplicantTest` fixture for its second signed-in applicant, not a generic extra-actor owner.

## Retained seams

- Disposable D1 fault tests retain direct trigger creation/drop because the required ABORT/IGNORE behavior must exercise the actual SQLite transaction. Triggers are scoped to synthetic actor IDs and are removed in `finally`; the fault and recovery assertions use the real application ingress.
- The lifecycle case uses native `caseApp.server.update` with a test-only `BETTER_AUTH_SECRET` rotation to force Wrangler's completed worker reload. It verifies stale-session denial, fresh sign-in with the same synthetic credential, exact same-key receipt replay, and unchanged D1 operation/audit rows. This is an observable native reload control, not a claim about ordinary production restart behavior.
- `readBoundedJson` retains the8,192-byte accepted parse bound and returns validation errors without synchronously draining rejected tails. Final independent review identified unrestricted discard in the background pipe. The inline repair retains native `waitUntil` but stops discarding after the same8,192-byte budget (at chunk granularity) and lets iterator return cancel the remainder. The native post-response lifetime cap still applies; no new timeout policy was introduced. A real production-helper stream regression fails on the reviewed source and passes the bounded repair; this Node stream check mocks only runtime scheduling/auth/DB dependencies and is not native ingress proof. Fresh finite-body native recovery remains required. Drain failures log only a fixed warning, never raw errors/request data.
- A separate finite Node HTTP control without a `Connection` override observed oversized JSON 400, text/plain 400, then a canonical 201 control, with independent D1 no-write and complete control-row checks. Its private diagnostic artifact is `.scratch/n06-node-finite-results`; the permanent same-request-context recovery case remains in the feature spec.
- Held-open slow-tail probes are diagnostic limitations, not passing acceptance claims: a one-byte invalid-media request against the original reader and an 8,193-byte held request against the waitUntil candidate did not return before the Playwright 120-second deadline; the public harness `server.fetch` probe also stalled. These probes do not identify the buffering boundary and are preserved privately in `.scratch/n06-original-reader-results`, `.scratch/n06-waituntil-results`, and `.scratch/n06-directprobe-results`. Final acceptance covers finite-body recovery and does not claim a response before slow EOF.

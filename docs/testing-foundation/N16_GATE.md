# N16 source-faithful native local gates

`pnpm test` remains the fast Vitest command. CI remains intentionally slim and unchanged: locked install, check, typecheck and fast Node tests; it is not full local qualification.

- `pnpm test:affected [--base <ref>] [--full]`: merge-base against `origin/main` by default, plus working/staged changes and eligible untracked source. Both sides of renames are classified with Git's `--no-renames` names. Missing PR base blocks; it does not silently choose HEAD.
- `pnpm test:staged [--full]`: exact Git index. Unknown paths block unless explicitly fully qualified; privacy still applies to full runs. Explicit staged `--full` includes the production build and complete native matrix.
- `pnpm test:staged --format`: indexed, locked formatter toolchain/config; native lint-staged hides/restores partial hunks and owns backup/revert. The newly formatted index is exported again for checks and selected required native tests.
- `pnpm test:e2e`: complete native foundation, features, causal and dev lanes; no legacy reset/migration/empty fallback lane.
- `pnpm test:qualify`: complete source candidate check/typecheck/fast Node/production build and complete native lanes.

The launcher imports only Node builtins until native Git exports the selected tree through an owned temporary index pinned with `read-tree <tree>`. The hook invokes Node directly, not an unstaged package-script trampoline. The exported snapshot owns selector/classifier, scripts, package/lockfile and project `.npmrc`; the snapshot module owns privacy and index invariants, while native Git export stays in the builtin-only launcher so mutable policy cannot run first. It never borrows the developer's node_modules or unstaged policy. Dependency bootstrap is visible `pnpm install --frozen-lockfile --prefer-offline`, with real locked install scripts and no hook-disable or ignore-scripts override. Separate empty user/global npm configs and a minimal environment prevent inherited developer credentials or npm/test policy from changing bootstrap. Required pinned Node/pnpm, dependencies, install scripts and command failures block.

Privacy guards inspect source before bootstrap: real variable files, non-placeholder examples, arbitrary-name structured auth/session/member records (including JSONC/BOM and CSV), SQLite magic, archive/raw report artifacts and unsafe index entries. Lexical JSONC comment/trailing-comma removal preserves string values and valid immutable migration/config metadata. Immutable TS scenario inputs and the public Design Book remain source; there is no docs-folder exemption. Error messages identify the offending path, never its contents. Native evidence lives under a fresh private external directory; disposable source/dependencies/state are removed in `finally`, with machine-readable source disposal/evidence locators. Native fixtures/runners retain runtime and store ownership; process-group signals only bound the native CLI invocation and its children. Evidence is private diagnostic material, not publishable masking proof.

Discovery uses native Playwright `--list --reporter=json`. Every selected tag must have actual cases; transport classification, expected skips/failures and duplicate HTTP execution block. Execution uses the same native projects/tags, no CLI grep override and no retries. Native JSON results must match discovered IDs/projects and every required case must pass its first and sole attempt. Native reporters own results and artifacts. No pass cache or new build-cache engine is introduced (N17 remains separate).

## Formatter research / implementation rationale

Context7 `/lint-staged/lint-staged` documents the native config/cwd API and partial-staging defaults. [Pinned v17.6.0 `lib/getSpawnedTask.js`](https://github.com/lint-staged/lint-staged/blob/v17.6.0/lib/getSpawnedTask.js) explicitly executes non-Git tasks in the provided cwd, **not** the config file's directory. Therefore merely pointing lint-staged at an indexed `.lintstagedrc.json` does not make the formatter authoritative. The indexed policy uses `node scripts/test-runner.ts format`; the gate resolves that task to the indexed runner and pinned Node and invokes native lint-staged with its explicit config. The format task runs indexed oxlint/oxfmt with separate absolute indexed configs and indexed tsconfig; pinned oxfmt 0.71.0 CLI help documents `--disable-nested-config`, preventing per-file unstaged nested formatter overrides. The installed Ultracite 7.12.2 fix dispatcher calls `Fl(s,o)` for oxlint but `Il(s,[])` for oxfmt: passthrough flags reach the linter, **not** the formatter. Explicit indexed formatter config and nested-config suppression therefore cannot be passed through Ultracite fix. The native commands preserve the same Ultracite presets without an additional formatter owner.

Pinned Playwright 1.63.0 JSONReporter strips `@` from serialized tags; the reporting boundary restores that marker before comparing the selection contract. Native JSON output-file environment precedence and source location serialization were checked in the installed pinned reporter source. These API/source observations establish implementation behavior, **not** candidate qualification.

[Native Git hook documentation](https://git-scm.com/docs/githooks) requires retaining local Git environment when operating on the invoking repository, and clearing it for foreign repositories. The launcher derives that context through native `git rev-parse --local-env-vars`, including `GIT_INDEX_FILE`, and pins the exported tree in a separate owned index. Git/lint-staged retain the real commit-index context; install/build/tests do not inherit it. Synthetic test repositories clear the invoking hook's Git context. [pnpm 10 install documentation](https://pnpm.io/10.x/cli/install) distinguishes store-first `--prefer-offline` from forced `--offline`, and explains that `ignore-scripts` disables real project/dependency lifecycle scripts. The gate rejects incompatible indexed offline/ignore-scripts policy rather than quietly bypassing it.

The behavioral tests use the actual gate/selector and locked dependency manifest in fresh synthetic Git repositories, not a second runtime framework. During implementation, run only changed-path checks and relevant counterexamples. Preserve successful evidence by exact source identity and scope; source or build-input changes require the affected evidence, not an unrelated full rerun. Freeze the contracted final candidate before complete qualification. The same matrix is not repeated merely to exercise each command alias; entrypoint-specific behavior uses targeted counterexamples. Capture-off/on parity remains a distinct required claim. There is one independent review after all implementation.

The main integration agent owns the single settled composed qualification and V7 synthetic counterexamples, including native execution/project totals, all prerequisite/failure cases and interrupt cleanup. No intermediate independent review or mid-flight build/lint/tests/formatter invocation is reported as a pass. No hook bypass is used for this source slice.

# Staff search projection upgrade

W08.C02 adds `person_profile.staff_search_key` through additive migration `0011_staff_search_projection.sql`. W19.C01 composes that producer with W03's original `0010_business_rate_limit.sql` in order. Original migrations and snapshots 0000–0009 remain unchanged, and the original 0010 snapshot is retained. The journal includes both producer entries; 0011's snapshot follows 0010 and includes its identical business-quota table. The existing schema composition remains the public owner; no additional SQL or schema facade is introduced.

The projection is the full name, one ASCII space, and display username (empty for NULL), followed by JavaScript `toLowerCase()`. It intentionally does not use the canonical sign-in key, width folding, or Unicode normalization. Search trims the query and validates at most 100 Unicode code points before case mapping. SQL `instr` receives the mapped query as a bound parameter, so `%`, `_` and backslash remain literal characters. Contact details are excluded.

Apply the additive migration before enabling search. Existing populated rows remain NULL until the application-owned `backfillStaffSearchProjectionBatch()` maintenance function runs. Each invocation selects at most 20 NULL rows and writes one native atomic batch, using the same JavaScript projection as identity writers. Conditional writes retain a concurrent identity change; a later invocation re-reads any remaining NULL row. Repeat until `complete` is true. `attempted` counts selected rows, not guaranteed writes. No HTTP maintenance endpoint or automatic production migration is introduced. Running this against remote or production data needs separate authorization.

Until every profile has a non-NULL projection, a nonempty search fails through the existing business error boundary instead of presenting incomplete results. An empty search retains the authorized bounded directory contract. Anonymous and assisted creation, applicant correction, and Staff identity correction maintain and assert the projection within their existing atomic batch. Replays do not rewrite newer identity state.

The producer's populated native upgrade scenario remains required.

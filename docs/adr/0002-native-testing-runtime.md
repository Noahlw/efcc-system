# Native built-app testing runtime

Authority: Spec #66 and ticket #67. This decision covers the runtime/provisioning boundary, not whole-suite qualification or downstream family migration.

## Ownership and contract

`tests/support/fixtures.ts` exports `NativeApp`, `openApp()` and Playwright `test`. Wrangler `createTestHarness` owns internal Worker ingress, workerd, storage, update/close and original D1 migration application. `srvx/node` owns the external loopback HTTP listener and delegates to native Harness `fetch()` routing, never a direct app handler or `getWorker().fetch()`. `NativeApp.close()` closes that listener and the harness with nested cleanup. `NativeApp.db` is obtained from **the app** `getEnv().DB`; consumers use native D1 statements directly, not a generic SQL facade. Playwright owns worker/test fixture lifetimes and fresh request/browser contexts. `app` reuses one store per execution worker; `dedicatedApp` owns a fresh store per case. Schema/global/race scenarios must use the latter. No scenario resets its store.

For migrated dedicated-store families, the test-scoped `caseApp` selects the resource target without adding a runtime owner: it defaults to worker-owned `app`, or native fixture overrides select `dedicatedApp`. Account provisioning, origin/headers, API login, Staff confirmation and authenticated browser state all depend on that same target. This composition is essential: aliasing dedicatedApp only in the test body leaves dependent account/request/context fixtures pointed at the worker store. A dedicated-store regression protects this invariant.

The app loads the actual `dist/server/wrangler.json` emitted by vinext, with portable relative metadata normalized by the build adapter (ADR0005). Asset/module/D1 identity remains intact. The bound loopback HTTP listener establishes the exact origin; `openApp()` supplies it to both workers in the initial `createTestHarness()` configuration before the Harness starts listening or either auth isolate is used. Synthetic secrets are native overrides, never developer `.dev.vars`. The provisioning Worker has the same D1 identity in the same harness, not another platform proxy/runtime owner.

The separate native HTTP listener is a transport compatibility seam: workerd closes idle HTTP/1 connections after five seconds without advertising that lifetime, and WebKit can lose the next non-idempotent POST at that boundary. Node 24 advertises its keep-alive timeout and adds its native close buffer. `srvx` supplies streaming, headers/cookies, cancellation, ephemeral listening and closure; EFCC does not implement an HTTP proxy. Native Requests pass through with `redirect: "manual"` so browser redirects remain observable. The small declaration casts bridge Node/undici and Worker global types without serializing their objects. Explicit fixture cleanup owns shutdown; srvx signal handlers are disabled.

`tests/worker/provision.ts` is a test-only default `WorkerEntrypoint`. `getExport().account(input)` delegates credential creation to production `getAuth().api.signUpEmail`, then supplies only necessary EFCC profile/role/name-key/timestamps/phone prerequisites. It does not issue sessions, fake hashes, clear tables, expose an HTTP Staff bootstrap, or import the production seed handler. Production build does not import this entry. HTTP login and password confirmation remain real production ingress operations. Native in-memory `request.storageState()` transfers genuine cookies to fresh browser contexts; never write auth snapshots.

`pnpm test:native` builds app and provisioning artifacts and runs the native proof config. Provisioning uses Wrangler dry-run only, not deployment. Lifecycle child probes run in a one-worker project after the ordinary project closes its stores; parent test-output paths own child artifacts. Runtime tests always run; no mutable state or passing result is cached.

Native qualification uses the authoritative Git snapshot and `native-test` build mode because Cloudflare can copy developer variables into emitted output. A filename-only guard rejects local variable files before plugin/harness startup without reading or deleting them. Native authenticated pages own a fresh context scoped to their case; public pages and other API clients retain their own identity. Acquired harness/context cleanup is nested so setup or restoration failures cannot skip closure.

## Alternatives and constraints

Rejected: a second D1 proxy, SQL CLI wrappers, copied seed HTTP handler, custom process/port manager, fake cookies, global counters, shared-store serial assumptions, or resets masquerading as persistent restart. The minimal EFCC seam is provisioning domain prerequisites; native libraries do not know EFCC membership/role/name matching. Public auth construction is unchanged. Causal pipeline controls and persistent update/reload durability are distinct evidence boundaries, documented in ADR0004; this RPC sidecar alone cannot prove them.

For the idle transport boundary, Wrangler 4.151 also reproduced the failure. Request/response `Connection` or `Keep-Alive` patches do not establish a safe wire contract: KJ owns those hop-by-hop headers. No vendor patch, heartbeat, delay, replay or test retry is retained. Native timeout configuration is currently a [workerd capability gap](https://github.com/cloudflare/workerd/issues/7169). Retire the srvx composition when native Harness HTTP ingress preserves the advertised idle lifetime and passes the same POST-boundary, auth, recovery and cleanup checks. The real Worker/router/D1 remain Wrangler-owned throughout; neither composition nor direct dispatcher access is evidence of Cloudflare remote edge/TLS behavior.

Historical source-scoped results and first failures: [#67](https://github.com/Noahlw/efcc-system/issues/67#issuecomment-6165611736). Current commands and extension guidance: [testing.md](../testing.md).

Configuration failures that prevent Worker initialization are native startup claims, not HTTP responses. Their cases use `@native @foundation @startup` and assert the actual Harness startup rejection, fixed attribution, secret non-disclosure and cleanup. The classifier requires exactly one boundary tag (`@http`, `@browser` or `@startup`); startup is restricted to the existing foundation lane, conflicts with transport tags and cannot claim mobile capability. Native discovery and execution still count these cases in full qualification.
